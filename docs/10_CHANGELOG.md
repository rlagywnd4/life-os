# Changelog

이 문서는 LifeOS 저장소의 사용자에게 의미 있는 변경을 시간순으로 기록한다. 세부 구현 의도와 이어받을 내용은 `docs/handoffs/`에 남기고, 제품/기술 결정은 `docs/09_DECISION_LOG.md`에 남긴다.

## 2026-07-20

- 네이티브 Inbox 수정 화면에서 미검토·언젠가·보관·폐기 상태를 메뉴로 선택해 제목·내용과 함께 저장할 수 있게 했다.
- iPhone에서 입력 중 다른 화면을 누르면 기존 버튼·메뉴 동작을 유지하면서 키보드가 내려가도록 했다.
- 운영 Supabase의 임시 계정으로 Inbox→Project 전환을 다시 검증해 Inbox 상태·프로젝트 연결·프로젝트 탭 조회가 한 트랜잭션으로 반영되는 것을 확인하고 테스트 데이터를 삭제했다.
- 운영 Supabase에서 개인 인증과 전체 네이티브 조회, Inbox CRUD·프로젝트 전환 RPC, 계층 활동, Today RPC, Someday, 주간 리뷰, 체중 목표, 건강 체크인을 임시 데이터로 통합 검증하고 생성 데이터를 모두 정리했다.
- XcodeGen 재생성 후에도 개인 Signing Team과 자동 서명이 유지되게 해 실제 iPhone 실행 때마다 Team을 다시 선택할 필요가 없도록 했다.
- 서명된 iPhone 빌드를 연결된 iPhone 15 Pro에 설치·실행하고 LifeOS 프로세스가 유지되는 것을 확인했다.
- 웹 대시보드를 네이티브 홈으로 옮겨 빠른 Inbox, 미검토 Inbox·활성 프로젝트·오늘 에너지·완료 행동 요약과 주요 화면 바로가기를 제공한다.
- Inbox 카테고리 필터와 Inbox→Project 트랜잭션 전환을 네이티브에 연결했다.
- 프로젝트 활동을 깊이 제한 없는 계층으로 표시하고, 활동 경로·하위 진행률·완료 제안·안전한 부모 변경·하위 활동 추가를 네이티브에 구현했다.
- 건강 체크인의 전체 식사·운동·컨디션 필드, 건강 프로필 설정, 단계별 체중 목표 CRUD, 최근 체중, 운동 루틴, 14일 행동 유지율과 피드백을 iPhone·Mac 공용 화면으로 옮겼다.
- 주간 리뷰 회고를 Supabase에 실제로 임시 저장할 수 있게 하고 최근 결과를 함께 표시한다.
- 네이티브 로그인 화면에 회원가입과 비밀번호 찾기를 추가하고 `lifeos://` 딥링크로 이메일 확인·비밀번호 재설정 흐름을 처리한다.
- iPhone 탭과 Mac 사이드바에 Today를 추가하고, 오늘 계획 저장·미완료 활동 조회·오늘 추가·핵심 선택·완료 처리를 기존 Supabase 데이터로 연결했다.
- 네이티브 Inbox에 추가·수정·삭제·검색과 언젠가·보관·폐기 상태 전환을 추가했다.
- 네이티브 앱에 프로젝트 상태별 목록과 상세, 활동 추가·수정·완료, 부모 활동 선택을 추가했다.
- 네이티브 앱에 Someday, 주간 리뷰 요약, 히스토리, 개인 설정 조회를 추가했다.

## 작성 규칙

- 기능, UX, 데이터 구조, 문서 운영 방식이 바뀌면 기록한다.
- 내부 리팩터링만 있고 사용자 영향이 없다면 짧게 기록하거나 handoff에만 남긴다.
- PRD 변경은 직접 기록하지 않고, 새 PRD 버전 반영 작업의 changelog로 기록한다.

## 2026-07-18

- iPhone·Mac에서 공용으로 실행되는 첫 SwiftUI 앱 기반을 추가하고, 기존 Supabase 계정으로 로그인해 `UNREVIEWED` Inbox를 읽을 수 있게 했다.
- 네이티브 앱은 Supabase를 단일 원본 데이터로 계속 사용하며, 앱에 서비스 역할 키·SwiftData·iCloud 동기화를 추가하지 않았다.
- Supabase 주소와 공개 키는 추적하지 않는 로컬 설정 파일로 분리해, 저장소와 PR에 개인 설정이 포함되지 않게 했다.

## 2026-07-19

- 네이티브 앱의 로컬 Supabase 설정이 기본 빈값으로 다시 덮어써지던 Xcode 설정 순서를 수정했다.
- Xcode 설정 파일의 URL이 `//` 뒤를 주석으로 처리하는 문제를 피하도록 Supabase URL 입력 형식과 앱 오류 안내를 보완했다.
- Supabase 설정을 생성형 Info.plist 키에 의존하지 않고 앱 전용 Info.plist에 직접 기록하도록 바꿔, 실행 중인 앱이 로컬 설정을 실제로 읽게 했다.
- 실제 iPhone 설치에 필요한 앱 식별자와 기본 번들 메타데이터를 네이티브 Info.plist에 추가했다.
- Git에서 제외된 개인 로컬 설정을 이용해 이메일·비밀번호를 입력하지 않고 로그인할 수 있는 "내 계정으로 로그인" 버튼을 추가했다.
- 네이티브 로그인 실패 시 비밀번호·이메일 인증·인터넷 연결·Supabase URL/키·서버 응답·요청 제한 원인을 구분해 안내한다.
- 네이티브 Inbox가 웹과 같이 미검토·프로젝트 전환·언젠가·폐기·보관 상태를 모두 표시하고 상태를 함께 보여주게 했다.

## 2026-07-17

- Git push는 SSH 키로, PR 자동화는 저장소 전용 GitHub App의 단기 토큰으로 처리하도록 인증 자동화를 추가했다.
- 기능 변경은 Preview 또는 테스트 빌드에서 사용자가 직접 확인한 뒤 PR로 병합하고, 단순 유지보수는 직접 커밋할 수 있도록 Git 컨벤션을 정리했다.
- 브랜치·커밋은 영문 Conventional Commit 형식으로, 사용자 확인용 PR 제목·본문은 한국어로 통일했다.
- 네이티브 앱의 AI 생각 정리 기능을 V1 이후 업그레이드 후보로 분리하고, V1에서는 iPhone·Mac 기본 흐름과 Supabase 동기화에 집중하기로 했다.
- 실제 프로덕션에서 임시 계정으로 계층형 활동 생성, 상위 경로, 부모 이동, 진행률, 완료 제안, 트리 접기·펼치기를 검증했다.
- 활동의 부모를 변경한 직후 수정 폼의 선택값이 이전 값으로 보이던 문제를 서버 갱신 시 폼을 다시 생성하도록 수정했다.
- 최초 Supabase migration history 복구와 후속 일반 배포 재실행을 완료하고 원격 DB가 최신 상태임을 확인했다.
- 기존 프로덕션 스키마와 migration history 불일치를 확인하고, 검증된 초기 스키마와 건강 모듈만 최초 1회 적용 완료로 기록하는 수동 복구 경로를 추가했다.
- 아직 적용되지 않은 생활 맥락 저장소와 활동 계층 마이그레이션은 history repair에서 제외하고 일반 DB migration으로 적용하도록 했다.
- 검증이 끝난 Codex 작업을 한국어 커밋과 Draft PR로 자동 게시하고, 기존 PR이 있으면 갱신하는 저장소 운영 규칙을 추가했다.
- `main` 배포 워크플로가 테스트와 애플리케이션 빌드 후 Supabase 마이그레이션을 dry-run하고 적용하도록 변경했다.
- Supabase CLI 버전을 고정하고 프로젝트 ref, access token, DB 비밀번호를 GitHub Actions variable/secret으로 주입하도록 구성했다.
- Vercel Git 자동 배포는 유지하고 GitHub Actions 체크를 Production Deployment Check로 사용해 마이그레이션 성공 전 프로덕션 승격을 막는 운영 절차를 추가했다.
- 애플리케이션 빌드와 데이터베이스 마이그레이션 순서를 검증하는 정적 테스트와 최초 migration history 정합성 절차를 추가했다.

## 2026-07-16

- 활동에 선택적인 부모 활동을 연결해 깊이 제한 없는 계층 구조로 세분화할 수 있게 했다.
- 프로젝트의 활동 목록을 들여쓰기 트리로 바꾸고 하위 활동 접기/펼치기를 추가했다.
- 활동 상세 화면에서 제목, 내용, 예상 시간, 부모 활동을 수정하고 하위 활동을 추가할 수 있게 했다.
- 활동 상세 화면에 프로젝트부터 현재 활동까지의 상위 경로를 표시한다.
- 부모 활동에 전체 하위 활동의 완료 개수와 진행률을 표시하고, 모두 완료되면 자동 완료 대신 명시적인 완료 제안을 표시한다.
- 같은 사용자와 프로젝트 안의 활동만 부모로 지정할 수 있고 순환 계층을 만들 수 없도록 데이터베이스 검증을 추가했다.
