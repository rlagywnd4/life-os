# AI

## Role

LifeOS에서 AI는 사용자를 대신해 인생을 결정하지 않는다. AI의 역할은 다음에 한정한다.

- 자연어 입력 구조화.
- 과거 기록과 대화 맥락 검색.
- 사용자 맥락 요약.
- Life Graph 관계 후보 생성.
- 반복 패턴 발견.
- 계획 현실성 점검.
- 현재 에너지에 맞는 행동 제안.
- 회고 질문 생성.
- 메시지, 문서, Codex 작업 지시 초안 작성.

## Guardrails

AI는 다음을 하지 않는다.

- 의료 진단 확정.
- 사용자의 가치관 임의 생성.
- 중요한 결정을 대신 확정.
- 과거 추론을 사실처럼 저장.
- 사용자를 부정적으로 낙인찍기.
- 불확실한 사실을 근거 없이 채우기.
- 지나치게 많은 행동을 한 번에 추천.
- 낮은 에너지를 의지 부족으로 해석.

## Memory Model

메모리는 다음 계층으로 구분한다.

1. Core Profile: 장기간 유지되는 가치, 선호, 제약.
2. Current State: 현재 직장, 체중, 프로젝트, 최근 목표처럼 변할 수 있는 정보.
3. Episode: 특정 여행, 갈등, 구매, 업무 사건.
4. Pattern: 여러 기록에서 발견된 반복 경향.
5. Hypothesis: AI가 추론했지만 아직 사용자 확인이 없는 정보.
6. Decision: 사용자가 명시적으로 정한 기준.

모든 AI 참조 가능 메모리는 다음 필드를 갖는 방향으로 설계한다.

- `source`
- `createdAt`
- `updatedAt`
- `confidence`
- `sensitivity`
- `validFrom`
- `validUntil`
- `status`
- `userConfirmed`

## Current Storage

현재 구현은 `life_context_documents`와 `life_context_entries`로 장기 컨텍스트 원문과 섹션을 저장할 수 있다. 공개 저장소에는 민감 원문을 두지 않고, 로컬 private seed에서 import한다.

## Native AI Future Upgrade

Native AI는 LifeOS V1의 구현 범위에서 제외한다. V1은 iPhone과 Mac에서 동일한 Supabase 데이터를 빠르고 안정적으로 다루는 기본 흐름을 완성하는 데 집중한다.

V1 이후 검토할 첫 기능은 사용자가 선택한 자유 메모 또는 Inbox 항목을 다음 형태로 제안하는 "생각 정리"다.

- 핵심 요약과 주제 분리.
- 아직 답하지 않은 질문.
- Inbox, 프로젝트, 다음 행동 후보.

구현을 시작할 때의 원칙은 다음과 같다.

- 지원 기기에서는 Apple Foundation Models 등 기기 내 모델을 우선 검토한다.
- Supabase는 동기화용 원본 데이터 저장소로 유지하고, AI는 앱이 사용자가 선택한 최소 범위의 데이터만 전달받는다.
- AI 제안은 자동 저장하거나 자동 실행하지 않는다. 사용자가 확인한 결과만 Inbox, 프로젝트, 활동에 반영한다.
- Apple Intelligence를 사용할 수 없는 기기에서도 LifeOS의 V1 핵심 흐름은 완전하게 동작해야 한다.
- 외부 AI 모델 또는 API 전송이 필요해질 경우, 대상 데이터와 동의 흐름을 별도의 제품·보안 결정으로 먼저 기록한다.
